## 【项目总览】

**项目目标**：构建 Windows、Linux、Android 三端双向互控的局域网远程控制软件，采用 Flutter（UI）+ Rust（核心）混合架构，共享一套代码基底。

**最终交付物**：可编译、可运行的三端客户端，包含设备发现、屏幕串流、输入注入、多会话管理、M3E 视觉、主题色系统、性能监控；附完整文档与发布包。

**适用范围**：纯局域网。支持 Win↔Lin 双向、Win/Lin↔Android 双向（含 Android 主控桌面端）。iOS/macOS 仅保留 Rust 抽象层，暂不实现 Flutter 平台。

**核心要求**：Win/Lin→Android 复用 scrcpy；Android→Win/Lin 采用开源方案优化；Flutter 负责 UI；Rust 负责网络、编码、捕获、解码、注入；三端 M3E 视觉一致；默认 QUIC，TCP 回退；主题色支持汲取、自定义、深色模式；性能工程贯穿全链路。

**成功标准**：三端互相发现并连接；默认 QUIC 建连；视频流局域网延迟 < 150ms；输入正确注入；多会话并行；主题色三端同步；项目可编译、可运行、可扩展。

# 全局关键路径

1. **第1段** 三端骨架 + M3E 主题 → **第2段** 设备发现与 QUIC/TCP 双传输层连接 → **第3段** 三方向核心链路 → **第4段** 完善优化 + 性能工程 → **第5段** 交付。
2. **最高风险**：第3.1段 scrcpy 协议集成、第3.3段跨平台屏幕捕获、第3.5段 Linux 输入注入（Wayland）、第4.4段硬件加速解码。
3. **最长链路**：第3.1 → 3.2 → 3.6 → 3.7（Win/Lin 控制 Android）。
4. **最易并行**：第3.3+3.4（捕获+编码）与第3.1+3.2（scrcpy）可同时推进。
5. **性能关键路径**：第4.8段性能工程 → 第4.9段性能监控 → 第5.3段验收。
6. **网络关键路径**：第2.1段协议 → 第2.3段 QUIC/TCP → 第4.5段 QoS → 第4.6段重连。
7. **界面关键路径**：第1.5段 M3E 主题 → 第4.7段 M3E 统一 → 第5.3段验收。
